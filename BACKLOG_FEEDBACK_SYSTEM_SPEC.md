# FightWeek Backlog & Feedback Management System
## Complete Technical Specification for Implementation in Another System

**Date:** February 14, 2026  
**Purpose:** This document describes the complete backlog and feedback management solution built into FightWeek, designed for agent-to-agent knowledge transfer.

---

## System Overview

The solution consists of two interconnected components:
1. **Backlog Management** - Kanban-style task board with keyboard shortcuts and bulk operations
2. **Feedback Collection** - In-app feedback gathering system that feeds into the backlog

Both systems are designed for high-velocity iteration and are optimized for keyboard power users.

---

## Data Model

### Backlog Collection Schema
```
{
  id: string                          // Generated by Firebase
  title: string                       // Task name
  desc: string                        // Detailed description
  acceptance: string                  // Acceptance criteria (multiline)
  notes: string                       // Internal notes
  status: 'backlog'|'todo'|'doing'|'done'
  tag: string                         // Category (e.g., 'APP', 'UI', 'API', etc.)
  priority: 'Low'|'Medium'|'High'     // Priority level
  release: string                     // Target release/milestone
  dataFields: string                  // Data-related info
  order: number                       // Sort order (floating-point for insertion)
  createdAt: ISO8601 string          // Creation timestamp
}
```

### Feedback Collection Schema
```
{
  id: string                          // Generated by Firebase
  text: string                        // Feedback message
  user: string                        // Email of user giving feedback
  userName: string                    // Display name of user
  timestamp: ISO8601 string          // When feedback was given
  context: string                    // Where feedback was given (e.g., 'Min Plan', 'Teamet', 'App')
  status: 'new'|'converted'|'dismissed'
  device: string                     // User agent string for debugging
}
```

## Core Features

### Feature 1: Real-Time Data Synchronization
- Uses Firebase Firestore queries with onSnapshot listeners
- Auto-sorts by `order` field on fetch
- Data updates instantly when another user makes changes
- No polling - subscription-based updates

### Feature 2: Kanban Workflow (4-Stage Pipeline)
1. **Backlog / Idé** → Raw ideas that need refinement
2. **To Do** → Prioritized, ready for development
3. **Doing** → Currently being worked on
4. **Done** → Completed, shipped, or closed

**Status Transitions:**
- Can move items forward/backward between stages
- Bulk operations support moving multiple items at once
- Single item can move to specific status directly

### Feature 3: Filtering System

**Filter Dimensions:**
1. **By Tag (Multi-select pattern):**
   - ALL (no filter)
   - APP (default tag)
   - Individual tags defined by tasks
   - Button-based toggle (light background = active filter)

2. **By Status:**
   - Active (everything except 'done')
   - Done (only completed items)
   - All (no status filter)

3. **By Search:**
   - Free-text search on title, description, and release fields
   - Case-insensitive, partial matches supported
   - Real-time as user types (no debounce)

**Constraint:** When filters are active, drag-and-drop sorting is disabled (must clear filters first)

### Feature 4: Selection & Bulk Operations

**Selection Model:**
- Multi-select with checkboxes or keyboard
- SelectionSet (using JavaScript Set) stores selected IDs
- Shows count in UI: "X selected"

**Bulk Operations Available:**
1. **Move to Status** - All selected items move in same direction (forward/backward)
2. **Move to Top** - All selected items moved to beginning of list
3. **Move to Bottom** - All selected items moved to end of list
4. **Copy to AI** - Exports selected tasks in formatted AI-friendly text
5. **Copy to Sheets** - TSV format for Google Sheets
6. **Export as CSV** - RFC 4180 CSV format
7. **Delete Multiple** - With confirmation dialog

**Context Menu:** Available when items selected (desktop nav bar shows action buttons)

### Feature 5: Data Import/Export

#### CSV Import
- **Delimiter Detection:** Auto-detects Tab, Semicolon, or Comma delimiters
- **Header Required:** First row must contain: `Titel`, `Beskrivelse`, `Status`, etc.
- **Modes:**
  - **Append Mode:** Adds imported tasks to existing backlog
  - **Replace Mode:** Clears existing backlog, loads new data
- **Modal Input:** Textarea with paste-friendly formatting
- **Field Mapping:**
  ```
  CSV Column       → Backlog Field
  Titel           → title (required)
  Beskrivelse     → desc
  Acceptkriterier → acceptance
  Noter           → notes
  Datafelter      → dataFields
  Status          → status (with smart mapping: "done"/"Færdig" → 'done', etc.)
  Tag             → tag (default: 'APP')
  Release         → release
  Prioritet       → priority
  Order           → order
  ID              → id (optional, for updating existing tasks)
  ```

#### CSV Export
- **Formats:** 
  - Standard CSV (comma-separated) or TSV (tab-separated for Sheets)
  - UTF-8 with BOM (Excel compatibility)
- **Scope:** All filtered tasks or selected tasks only
- **Columns:** All task fields
- **Clipboard:** Directly copied, not downloaded

#### JSON Export (Power User)
- Exports both backlog and feedback collections as JSON
- Used for backup/archival purposes

### Feature 6: Feedback to Task Conversion

**Flow:**
1. User submits feedback in-app (see Feedback Collection below)
2. Admin sees feedback in "Inbox" tab with "Opret Opgave" button
3. Clicking button pre-fills new task form:
   - Title: Feedback text
   - Description: Includes original feedback, user name, device info
   - Status: Set to 'todo' (not backlog)
   - Context: Preserved in description
4. Admin can edit, add acceptance criteria, etc.
5. Saving the task auto-updates feedback status to 'converted'

## Feedback Collection System

### Where Feedback Can Be Triggered

1. **Training Schedule View (Personal):**
   - Button in view selector: 💬 "Min Plan" context
   - Clicking feedback icon opens FeedbackModal pre-filled with context="Min Plan"

2. **Training Pass (SessionModal):**
   - Message icon in training pass details
   - Sets context to activity name (e.g., "Pas: Wall Wrestling")

3. **Team Schedule View:**
   - Button in view selector: 💬 "Teamet" context
   - Context shows as "Team Schedule"

### Feedback Collection Modal

**UI:**
- Modal overlay (z-index: 80)
- Textarea input (4 rows, monospace placeholder text)
- "Luk" (Close) and "Send" buttons

**On Submit:**
- Validates that text is not empty
- Records:
  - User email + mapped user name
  - Timestamp (ISO 8601)
  - Context (where feedback was given)
  - Device info (full user agent)
  - Status: 'new' (marks as unread)
- Shows toast: "Tak for feedback!" (Thank you for feedback!)
- Closes modal

**Data Stored to:** `artifacts/production/public/data/feedback` collection

### Feedback Status Lifecycle

1. **new** - Just received, appears in inbox with blue highlight
2. **converted** - Admin created a task from this feedback, dimmed in inbox
3. **dismissed** - (Optional) Admin rejected without creating task

## Advanced Features

### 1. Smart Task Ordering
- Floating-point order values allow insertion without reordering entire list
- New tasks inserted with order = (prevOrder + nextOrder) / 2
- If no next item, order = prevOrder + 1000
- New items created at negative timestamp: `-Date.now()` (sorts to top)

### 2. Drag & Drop (Desktop only - touch disabled)
- Disabled on mobile devices
- Disabled when filters are active
- Shows opacity feedback (0.5) while dragging
- Reorders entire filtered list on drop
- Batch updates all affected order values

### 3. In-App Browser Detection
- Detects Facebook/Instagram in-app browsers (user agent check)
- Blocks login with message: "Brug Chrome eller Safari"
- Forced browser redirect via link copy

### 4. Mobile Optimization
- Responsive design (max-width: 768px media queries)
- Touch-friendly button sizing
- No drag-and-drop on touch
- Vertical layout for narrow screens
- Monospace devices detected and disabled for some features

### 5. AI-Friendly Export Format
```
OPGAVE: {title}
STATUS: {status}
BESKRIVELSE: {description}
ACCEPTKRITERIER: 
{accepts criteria with auto-numbered if not already}
NOTER: {notes}
--------------------------------------------------
```
- Numbers acceptance criteria if not already numbered
- Preserves multi-line formatting
- Shows "(Ingen/None)" for empty fields

## Error Handling

### User-Facing Errors
- All operations wrapped in try-catch
- Errors show alert() popup (could be improved to toast)
- Validation: Check required fields before submit
- Constraints: Cannot move items when filters active (explicit alert)

### Data Validation
- CSV: Checks for at least one row with "Titel" field
- Import: Smart status mapping (case-insensitive)
- Task: Title required before save
- Selection: Operations no-op if selection empty

### Confirmation Dialogs
- Delete task(s): "Er du sikker? Denne handling kan ikke fortrydes."
- Bulk delete: Shows count "Slet X opgaver?"
- Unsaved changes: Warns before closing form without saving

## Performance Considerations

### Real-Time Updates
- Firestore `onSnapshot` listeners for auto-sync
- No polling, subscription-based
- Multiple collections queried simultaneously (backlog + feedback)

### Bulk Operations
- WriteBatch API for atomic multi-document updates
- All updates sent in single batch.commit()
- No individual saves

### Search & Filter
- Runs in-memory (no server-side search)
- Recalculates on every change using useMemo
- Case-insensitive substring match

## Code Architecture Notes

**Frontend Framework:** React 18.2.0 (could be adapted to Vue, Svelte, etc.)

**State Management Pattern:**
- useState for UI state (modals, focus, selection)
- Firebase Firestore onSnapshot for data state
- useMemo for filtered/computed data

**Database:** Firebase Firestore (No-SQL)
- Real-time sync via listeners
- Atomic batch updates
- Collection-based structure

**UX & Performance:**
- Keyboard-first design
- Single-page all-views
- No page refreshes needed
- Responsive design (mobile-first)

---

## Known Limitations

1. **Search:** Client-side only - useful up to ~500 tasks before performance degrades
2. **Drag & Drop:** Desktop only, disabled on mobile and when filters active
3. **Batch Size:** No practical limit (Firebase Firestore supports batches up to 500 documents)
4. **Real-Time:** Requires persistent connection; works offline but won't sync
5. **Auth:** Email-based access control only (no fine-grained permissions)
